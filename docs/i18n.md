# Internationalization (i18n)

ポータルの多言語対応 (日本語と英語) の URL 戦略、route 配線、リソース運用、翻訳なし fallback。`architecture.md` の zones に従い、i18n runtime は `app/lib/i18n/` に集約する。

## URL 戦略

**ja default 無 prefix + en だけ `/en/...` prefix** を採用する。

```
/                              ja トップ
/databases/bioproject          ja
/search/results?q=cancer       ja
/en                            en トップ
/en/databases/bioproject       en
/en/search/results?q=cancer    en
```

採用理由 (代替案との比較含む) は `decisions.md` の「URL 戦略は ja default 無 prefix + `/en/...` のみ prefix」 を参照。

### 言語の決定

ロケールは **URL から一意に決まる**。Cookie / Accept-Language / localStorage で挙動を変えない:

| URL 開始位置 | ロケール |
|---|---|
| `/en` または `/en/...` | `en` |
| 上記以外 | `ja` |

これにより同じ URL を共有すれば誰が踏んでも同じ言語で表示される。Accept-Language 等の自動切替は採用しない (User-Agent 推測による無断切替は意図しない言語表示を招くため)。

## routes 配線

URL 戦略 (ja default + `/en/...` prefix) は **route id を変えて同じ route component を二重宣言** することで実装する。配線詳細 (`bilingualRoutes` helper、`lang-en` layout、id 命名規則、PBT 不変量) は `routes.md` を参照。

i18n 視点で押さえる点:

- en 側 layout (`app/routes/lang-en/layout.tsx`) は `handle = { lang: "en" as const }` を持つだけの薄い `<Outlet />`。ja 側は handle を持たず default で ja として解決される
- lang は **URL から静的に決まる** ため、loader (非同期 data fetch) ではなく handle (静的 metadata) で表現する。これにより `createRoutesStub` を使った unit test で loader 実行を起こさずに lang を注入できる (jsdom + undici 互換性確保)

## useLang hook

### シグネチャ

```ts
// app/lib/i18n/use-lang.ts (抜粋)
export type Lang = "ja" | "en"

export const determineLang = (matches: readonly { handle: unknown }[]): Lang =>
  matches.some(
    (m) => !!m.handle
      && typeof m.handle === "object"
      && (m.handle as { lang?: Lang }).lang === "en",
  ) ? "en" : "ja"

export const useLang = : Lang => determineLang(useMatches)
```

`determineLang` を別 export しているのは、React Router の `useMatches` に依存しない純粋関数として unit / PBT でテストするため。`useLang` は薄い hook wrapper。

### 使い方

```tsx
import { useLang } from "~/lib/i18n/use-lang"
import { useT } from "~/lib/i18n"

function PageTitle {
  const lang = useLang
  const t = useT
  return <h1>{t("page.title")}</h1>
}
```

`useT` は react-i18next の `useTranslation` ベース、`useLang` の結果に同期して切り替わる。

## リソース運用

### 静的 import

```
app/lib/i18n/
├── index.ts                  i18next init + Provider
├── use-lang.ts               useLang hook
├── use-t.ts                  useT hook (react-i18next wrapper)
└── resources/
    ├── ja.ts                 ja リソース (Record<string, ...>)
    └── en.ts                 en リソース (同上)
```

リソースは **静的 import** する。動的 import / lazy load は本リリースでは採用しない (URL から言語が決まるので最初から該当言語だけ読めるが、bundle サイズが膨張するまで分離は不要)。

### キー設計

ネスト構造を平坦化したドット記法で扱う:

```ts
// app/lib/i18n/resources/ja.ts
export const ja = {
  common: {
    appName: "DDBJ ポータル",
    loading: "読み込み中",
    error: "エラー",
  },
  nav: {
    top: "トップ",
    search: "検索",
    submit: "登録",
    news: "ニュース",
  },
  breadcrumb: {
    home: "ホーム",
    databases: "データベース",
  },
  switchLang: {
    toEn: "Switch to English",
    toJa: "日本語",
  },
  translationUnavailable: {
    title: "この page の英語訳は未提供です",
    description: "日本語版を表示しています。翻訳の追加を予定しています。",
  },
} as const
```

`en.ts` も **同じキー構造** を持つ。キーセットの整合は PBT で検証する。

### リソースから取り出す関数

```ts
// app/lib/i18n/use-t.ts
import { useTranslation } from "react-i18next"

export type TFn = (key: string, options?: Record<string, unknown>) => string

export const useT = : TFn => {
  const { t } = useTranslation

  return (key, options) =>
    (options === undefined ? t(key) : t(key, options)) as string
}
```

`options` を渡さないとき / 渡すときで react-i18next の overload を分岐させ、戻り値を `TFn` 型に統一する。

## 翻訳なし fallback

### 挙動

en page で対応キーが en リソースに存在しない場合:

1. ja のキーを fallback として表示する (page が空にならない)
2. `<TranslationUnavailable />` バナーをページ上部に表示する
3. バナーには "Switch to Japanese" リンクで ja URL に飛べる導線を置く
4. URL は `/en/...` のまま (リダイレクトしない、SEO 上の重複を避ける)

### react-i18next 設定 (request-scoped instance)

`app/lib/i18n/index.ts` が `createI18nInstance(lng)` を export する。これを 1 request ごとに新しく作り、`<I18nextProvider i18n={instance}>` に渡す。

```ts
// app/lib/i18n/index.ts (抜粋)
import { createInstance, type i18n as I18nInstance } from "i18next"
import { initReactI18next } from "react-i18next"

import { en } from "./resources/en"
import { ja } from "./resources/ja"

export const createI18nInstance = (lng: Lang): I18nInstance => {
  const instance = createInstance
  instance.use(initReactI18next).init({
    resources: { ja: { translation: ja }, en: { translation: en } },
    lng,
    fallbackLng: "ja",
    interpolation: { escapeValue: false },
  })
  return instance
}
```

`fallbackLng: "ja"` により、`t("foo.bar")` が en に未定義なら ja の値が返る。

`app/root.tsx` 側:

```tsx
import { useMemo } from "react"
import { I18nextProvider } from "react-i18next"
import { createI18nInstance } from "~/lib/i18n"
import { useLang } from "~/lib/i18n/use-lang"

function AppShell {
  const lang = useLang
  const i18n = useMemo( => createI18nInstance(lang), [lang])
  return (
    <I18nextProvider i18n={i18n}>
      <Outlet />
    </I18nextProvider>
  )
}
```

これにより SSR の並列 request で異なる lng の `changeLanguage` がレースすることがない (同一プロセスが複数の request を同時に処理する場合でも、各 request は独立した instance を持つ)。

### TranslationUnavailable バナー

`app/shell/translation-unavailable.tsx` で実装する。「現在の URL 配下に翻訳キーが不足しているか」 を判定する基準は、route 単位の翻訳完了 flag を `route handle` で持たせる:

```ts
// app/routes/news/route.tsx (抜粋)
export const handle = {
  i18n: { en: "complete" },  // "complete" | "missing" | "partial"
} as const
```

`<TranslationUnavailable />` は `useMatches` を辿り、現在 lang が `en` かつ いずれかの match の `handle.i18n.en` が `"complete"` 以外であれば表示する。ja URL では何も表示しない。

route handle に `i18n` flag を書かない route は「complete」 とみなす。ja 側 route には flag を書かない (ja default なので不要)。PBT で ja / en キーセットの整合が担保されているので、en 側の翻訳が物理的に欠落した場合は CI で検出される — handle flag は「翻訳が論理的に未完成な page」 を運用上マークするための仕組み。

## SEO

### hreflang 宣言

`app/root.tsx` で現在 URL から対応 URL を計算し、`<link rel="alternate">` を 2 方向で宣言する。

```tsx
// app/root.tsx (抜粋)
import { useLocation } from "react-router"
import { useLang } from "~/lib/i18n/use-lang"
import { getCounterpartUrl } from "~/lib/i18n/url"

function HreflangLinks {
  const lang = useLang
  const location = useLocation
  const jaUrl = lang === "ja" ? location.pathname : getCounterpartUrl(location.pathname, "ja")
  const enUrl = lang === "en" ? location.pathname : getCounterpartUrl(location.pathname, "en")
  return (
    <>
      <link rel="alternate" hrefLang="ja" href={jaUrl} />
      <link rel="alternate" hrefLang="en" href={enUrl} />
      <link rel="alternate" hrefLang="x-default" href={jaUrl} />
    </>
  )
}
```

### URL 変換ヘルパ

```ts
// app/lib/i18n/url.ts
import type { Lang } from "./use-lang"

export function getCounterpartUrl(pathname: string, target: Lang): string {
  if (target === "en") {
    if (pathname === "/") return "/en"
    return `/en${pathname}`
  }
  // target === "ja"
  if (pathname === "/en") return "/"
  if (pathname.startsWith("/en/")) return pathname.slice(3)
  return pathname
}
```

### Switch language リンク

`app/shell/switch-lang.tsx` で実装し、Header から呼ぶ。現在 URL の対応 URL に飛ばす:

```tsx
// app/shell/switch-lang.tsx (抜粋)
import { Link, useLocation } from "react-router"
import { useLang } from "~/lib/i18n/use-lang"
import { useT } from "~/lib/i18n"
import { getCounterpartUrl } from "~/lib/i18n/url"

export const SwitchLang =  => {
  const lang = useLang
  const { pathname } = useLocation
  const t = useT
  const target: Lang = lang === "ja" ? "en" : "ja"
  const key = target === "en" ? "switchLang.toEn" : "switchLang.toJa"
  return <Link to={getCounterpartUrl(pathname, target)}>{t(key)}</Link>
}
```

## テスト

### PBT: ja / en キー整合

`tests/pbt/lib/i18n.pbt.test.ts` で `ja` と `en` リソースの **同一キーセット保有** を検証する:

```ts
import { en, flattenKeys, ja } from "~/lib/i18n"

const jaKeys = flattenKeys(ja).sort
const enKeys = flattenKeys(en).sort

test("i18n_jaEnKeySets_areEqual",  => {
  expect(enKeys).toEqual(jaKeys)
})
```

`flattenKeys` は `app/lib/i18n/flatten-keys.ts` で、ネストオブジェクトを `"a.b.c"` 形のドット記法 string の配列に展開する。配列・null・scalar を leaf とみなす。これにより「ja にだけある / en にだけある」キーを早期検出する。

### URL 変換ヘルパの不変量

`getCounterpartUrl` の round-trip 不変量を PBT で固定する:

```ts
test.prop([fc.webPath])("i18n_counterpart_isReciprocal", (path) => {
  const en = getCounterpartUrl(path, "en")
  const back = getCounterpartUrl(en, "ja")
  // 元 path に正規化を適用した形と等価
  expect(normalize(back)).toBe(normalize(path))
})
```

# Internationalization (i18n)

ポータルの多言語対応 (日本語と英語) の URL 戦略、lang 解決ルール、リソース運用、翻訳なし fallback。`architecture.md` の zones に従い、i18n runtime は `app/lib/i18n/` に集約する。

## URL 戦略

**URL から lang を排除し Cookie で管理する**。同じ path が両言語を表す:

```
/                              top
/databases/bioproject          database detail
/search/results?q=cancer       search results
/news                          news index
```

`/en/...` のような prefix も `?lang=` の常時付与も用いない。SwitchLang を踏んでも URL は変わらず、ページ全体が in-place で切り替わる。採用理由 (代替案との比較含む) は `decisions.md` の「URL から lang を排除し Cookie で管理する」 を参照。

### lang 解決の優先順位

1. URL の `?lang=ja|en` (読み取り専用 hint)
2. cookie `db_portal_lang` (`ja` or `en`)
3. `Accept-Language` ヘッダ (`ja*` を優先、`en*` なら `en`、それ以外は ja)
4. fallback `ja`

`?lang=ja|en` が指定されたときは root loader が cookie を上書きし、`?lang` を落とした URL に 302 redirect する (cookie を「stick」 させた状態で URL を綺麗にする)。初回訪問で cookie が無く Accept-Language で言語が決まった場合も cookie を発行する。

priority chain は純粋関数 `resolveLangFromRequest` (`app/lib/i18n/resolve-lang.server.ts`) に閉じ込め、PBT で「任意入力に対して常に `ja|en` を返す」「`?lang=ja|en` 指定時はその値を返す」 不変量を担保する。

## root loader での実装

`app/root.tsx` の `loader` が次を行う:

```ts
// 擬似
export const loader = async ({ request, context }: LoaderFunctionArgs) => {
  const url = new URL(request.url)
  const hint = url.searchParams.get("lang")

  if (hint === "ja" || hint === "en") {
    url.searchParams.delete("lang")
    const headers = new Headers()
    headers.append("Set-Cookie", await langCookie.serialize(hint))
    throw redirect(url.pathname + url.search, { headers, status: 302 })
  }

  const cookieLang = await langCookie.parse(request.headers.get("Cookie") ?? "")
  const lang = cookieLang ?? resolveFromAcceptLanguage(request.headers.get("Accept-Language"))
  const stickyHeaders = cookieLang === undefined
    ? { "Set-Cookie": await langCookie.serialize(lang) }
    : undefined

  return data({ lang, cspNonce: context.cspNonce }, stickyHeaders ? { headers: stickyHeaders } : undefined)
}
```

`lang` を loaderData に乗せ、`<LangProvider value={lang}>` で全 component に配る。

## useLang hook

```tsx
// app/lib/i18n/use-lang.ts (抜粋)
import { useContext } from "react"
import { LangContext } from "./lang-context"

export type Lang = "ja" | "en"

export const useLang = (): Lang => {
  const lang = useContext(LangContext)
  if (lang === null) throw new Error("useLang must be used within LangProvider")
  return lang
}
```

Provider 配下でなければ throw する (SSR で root loader → Provider の経路を必須にし、暗黙の default 値が紛れ込まないようにする)。`useLang(): Lang` の signature は固定で、call site は import path を含めて変わらない。

### 使い方

```tsx
import { useLang } from "~/lib/i18n/use-lang"
import { useT } from "~/lib/i18n"

function PageTitle() {
  const lang = useLang()
  const t = useT()
  return <h1>{t("page.title")}</h1>
}
```

`useT` は react-i18next の `useTranslation` ベース、`useLang` の結果に同期して切り替わる。

## lang cookie

`app/lib/i18n/lang-cookie.server.ts` で定義する:

| attr | 値 | 根拠 |
|---|---|---|
| name | `db_portal_lang` | 既存 `sid` cookie 命名 (短い snake) と整合、prefix で衝突回避 |
| `HttpOnly` | `false` | lang は機密でない。将来 client からの参照余地を残す |
| `SameSite` | `Lax` | 既存 `sid` と揃える。`Strict` だと top-level navigation で消える |
| `Secure` | `secureRuntime(env)` (`server/auth/cookie.ts` のパターンに合わせる) | dev (http://localhost:3000) では落とす |
| `Path` | `/` | 全 URL で同じ lang |
| `Max-Age` | `60*60*24*365` (1 年) | 言語選択は長持ちさせる |
| `Domain` | 未指定 | サブドメイン共有不要 |

## SwitchLang resource route

`app/routes/api.set-lang.ts` を resource route として定義する (default export なし、`action` のみ)。`useFetcher().submit({ lang }, { method: "post", action: "/api/set-lang" })` で submit すると RR は全 active loader を revalidate するため、root loader が新 lang を返し → `<LangProvider>` 値が変わり → 全 page が新 lang で再 render される。URL は変化しない。

```ts
// app/routes/api.set-lang.ts (抜粋)
import { z } from "zod"
import { redirect } from "react-router"
import { langCookie } from "~/lib/i18n/lang-cookie.server"

const langSchema = z.union([z.literal("ja"), z.literal("en")])

export const action = async ({ request }: ActionFunctionArgs) => {
  const formData = await request.formData()
  const lang = langSchema.parse(formData.get("lang"))
  const redirectTo = request.headers.get("Referer") ?? "/"
  return redirect(redirectTo, {
    status: 303,
    headers: { "Set-Cookie": await langCookie.serialize(lang) },
  })
}
```

Header の `SwitchLang` も `<TranslationUnavailable>` の「Switch to Japanese」 動線も、共通でこの resource route に POST する `<fetcher.Form>` で実装する。

## リソース運用

### 静的 import

```
app/lib/i18n/
├── index.ts                  i18next init + 公開 API
├── use-lang.ts               useLang hook (Context 参照)
├── use-t.ts                  useT hook (react-i18next wrapper)
├── lang-context.tsx          LangProvider / LangContext
├── lang-cookie.server.ts     cookie 定義 (server 専用)
├── resolve-lang.server.ts    priority chain (server 専用)
└── resources/
    ├── ja.ts                 ja リソース
    └── en.ts                 en リソース
```

リソースは **静的 import** する。動的 import / lazy load は本リリースでは採用しない。

### キー設計

ネスト構造を平坦化したドット記法で扱う:

```ts
// app/lib/i18n/resources/ja.ts
export const ja = {
  common: {
    appName: "DDBJ ポータル",
    loading: "読み込み中",
    error: "エラー",
  },
  nav: { top: "トップ", search: "検索", submit: "登録", news: "ニュース" },
  breadcrumb: { home: "ホーム", databases: "データベース" },
  switchLang: { toEn: "Switch to English", toJa: "日本語" },
  translationUnavailable: {
    title: "この page の英語訳は未提供です",
    description: "日本語版を表示しています。翻訳の追加を予定しています。",
  },
} as const
```

`en.ts` も **同じキー構造** を持つ。キーセットの整合は PBT で検証する。

### react-i18next 設定 (request-scoped instance)

`app/lib/i18n/index.ts` が `createI18nInstance(lng)` を export する。これを 1 request ごとに新しく作り、`<I18nextProvider i18n={instance}>` に渡す。

```ts
// app/lib/i18n/index.ts (抜粋)
export const createI18nInstance = (lng: Lang): I18nInstance => {
  const instance = createInstance()
  instance.use(initReactI18next).init({
    resources: { ja: { translation: ja }, en: { translation: en } },
    lng,
    fallbackLng: "ja",
    interpolation: { escapeValue: false },
  })
  return instance
}
```

`fallbackLng: "ja"` により、`t("foo.bar")` が en に未定義なら ja の値が返る。

## 翻訳なし fallback

### 挙動

en でレンダリング中に対応キーが en リソースに存在しない場合:

1. ja のキーを fallback として表示する (page が空にならない)
2. `<TranslationUnavailable />` バナーをページ上部に表示する
3. バナーには「Switch to Japanese」 リンクで cookie 切替する動線を置く (URL 不変)

### TranslationUnavailable バナー

`app/shell/translation-unavailable.tsx` で実装する。現在 lang が `en` かつ いずれかの match の `handle.i18n.en` が `"complete"` 以外であれば表示する。ja 表示時は何も表示しない。

「Switch to Japanese」 部分は `<fetcher.Form method="post" action="/api/set-lang">` + hidden `lang=ja` の link 風 button で実装する。submit すると root loader が再評価され、URL を変えずに ja に切り替わる。

route handle 規約は `routes.md` の `handle.i18n.en` を参照。

## SEO

### hreflang 宣言

`app/root.tsx` の `meta()` で、現在 path について `?lang=ja` / `?lang=en` / `x-default` の `<link rel="alternate">` を出力する:

```tsx
<link rel="alternate" hrefLang="ja" href={`${origin}${pathname}?lang=ja`} />
<link rel="alternate" hrefLang="en" href={`${origin}${pathname}?lang=en`} />
<link rel="alternate" hrefLang="x-default" href={`${origin}${pathname}?lang=ja`} />
```

`?lang=` を踏んだ crawler は root loader の redirect で cookie が立った状態の path に着地し、目的の言語で indexable になる。

### sitemap.xml

`server/api/sitemap.ts` が各 path について `?lang=ja` / `?lang=en` の 2 URL を出力し、`<url>` 内に `<xhtml:link rel="alternate" hreflang="...">` を相互宣言する (Google 推奨形式)。`<urlset>` は `xmlns:xhtml="http://www.w3.org/1999/xhtml"` を宣言する。

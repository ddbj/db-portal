# Contact

問い合わせ窓口ページ (`/contact`) の位置づけ、 窓口の振り分け、 窓口の提示方法。

## 位置づけ

BSI ポータル自体 (使い方 / 掲載内容 / 表示の不具合) の一次窓口を 1 ページに集め、 それ以外の相談は既存の運用窓口へ送る。

送信 form を持たず、 利用者のメールクライアントで作成・送信してもらう。 BFF は問い合わせ内容を受け取らず、 このページに紐づく endpoint は存在しない。

## 窓口の振り分け

| 相談内容 | 送り先 |
|---|---|
| BSI ポータルの使い方 / 掲載内容 / 表示の不具合 | BSI ヘルプデスク |
| 各 DB へのデータ登録 / 公開 / 登録内容の更新 | DDBJ お問い合わせ |
| DBCLS が提供するデータベース / ツール | DBCLS お問い合わせ |
| 遺伝研スーパーコンピュータの利用 | 遺伝研スパコン質問窓口 |

宛先アドレスと外部窓口 URL の SSOT は `app/features/contact/helpdesk.ts`。 外部窓口は ja / en で別 URL を持つ。

窓口へ送る前に自己解決できる導線 (ナレッジベース / DDBJ FAQ / サービス一覧) をメール窓口より上に置く。

## 窓口の提示

`mailto:` link は置かない。 メールクライアントが開く保証は環境ごとに異なり、 Web メール利用者には何も起きない。 窓口の手段はアドレスの平文表示とコピーの 2 つに固定する。

- 宛先アドレスは選択可能な平文テキストとして表示する
- コピーボタンを併置し、 押下から一定時間だけ成功フィードバックを出す。 フィードバックは `role="status"` でも通知する
- clipboard API が使えない環境ではフィードバックを出さず、 表示中のアドレスの手動選択に委ねる
- 問い合わせに書いてほしい項目はページ本文に一覧で示す

## レイアウト

枠線カードはリンク (自己解決導線と他の問い合わせ先) にだけ使い、 メール窓口には使わない。 カードの寸法と間隔は top page の service grid に合わせ、 セクションをまたいで列数を揃えることでカード 1 枚の幅をページ内で一定に保つ。

## 導線

`/contact` への入口は 3 つ。 ページを増減させたときは 3 つとも合わせる。

- header の main nav
- `/docs` 目次 — `page-contents/sitemap.json` の `support` セクション
- `/sitemap.xml` — `server/api/sitemap.ts` の `STATIC_PATHS`
